# NPC 跟随 NPC 实测（2026-09-30）

结论：原版 JAR 在完整整合包的隔离服务端中可以正常步行跟随。身份与职业同时选择随从会复现“找到目标但不移动”；NoAI、坐姿、错误目标名及速度为零也分别复现不动。解除这些限制后，全部恢复步行。没有修改正式 NPC 或模组业务代码。

## 环境和方法

- 原版 `CustomNPCs-Unofficial-NeoForge-1.21.1.20251230.jar`，SHA256 `6c28d87b215fc1191488194188ec8a39dd908ae7d2d887b7c9d7d463be0a162c`。
- Minecraft 1.21.1 / NeoForge 21.1.250 / Java 21；339 个顶层模组 JAR（含测试器），6G 堆、4 个逻辑处理器。
- 独立世界、回环端口 25588；目录 `D:\CPN\work\npc-follower-test\original`。
- 六组 NPC，各组隔开 48 格，使用唯一目标名；石质平坦跑道，强制加载相关区块，无战斗目标。
- 领队保持静止，随从从 10 格外开始；每 tick 记录随从真实位置，每 10 tick 保存诊断轨迹。
- 第一阶段观察 260 tick；第二阶段解除该组限制，把领队向前移 6 格，再观察 280 tick。测试器从未移动随从，也没有手动调用它的跟随 AI 或导航，只让真实服务端 tick 驱动。
- 正常组使用“身份：无、职业：随从、移动：站立、移动方式：行走、动画：普通、速度：5”。**“移动：站立”本身不会禁止职业随从跟随。**

## 结果

| 配置 | 第一阶段随从位移 | 解除限制后位移 | 最终与领队距离 |
| --- | ---: | ---: | ---: |
| 正常配置 | 8.35 格 | 5.86 格 | 1.86 格 |
| 身份与职业都为随从 | 0 格 | 14.29 格 | 1.76 格 |
| NoAI=true | 0 格 | 14.29 格 | 1.76 格 |
| 坐姿动画 | 0 格 | 14.29 格 | 1.71 格 |
| 目标名字不匹配 | 0 格 | 14.29 格 | 1.76 格 |
| 移动速度为 0 | 0 格 | 14.29 格 | 1.76 格 |

12 项阶段检查均符合预期。正常组首次开始移动约在创建后 102 tick（20 TPS 下约 5.1 秒）；禁用 AI 组解除禁用后也有类似目标搜索等待。因此新设置后应留出几秒，而不是立即判为失败。

正常组第一阶段最大单 tick 位移 0.225 格；恢复阶段各组均不超过 0.369 格，记录中未出现远距离传送。限制组的 0 格是实际 x/y/z 位移为零，不是仅凭画面判断。

身份冲突组的职业已经找到领队，但 `getOwner()` 返回空：实体代码优先读取身份随从的玩家主人，该身份未雇佣时不会回退到职业随从的 NPC 目标。将身份改为“无”后目标解析和移动恢复。

## 排查用户 NPC

先确认高级设置“身份：无、职业：随从”，动画普通、速度 5、移动方式行走，目标名称直接从列表选择，两个 NPC 相隔 8–10 格，退出编辑器后等待数秒。

此前自动库存测试创建的“库存验证商人”明确设有 `NoAI=true`，若拿它测试跟随，需解除 NoAI 或另建普通 NPC。此记录没有确认用户正在使用哪一个实体，因此不能将这些条件中的某一项直接宣布为其现场故障原因。

## 重现

`python tools/npc_stock_audit.py --suite follower --java-home <JDK21目录> --output <测试器输出目录>`

把生成的 `follower_audit-local-only.jar` 放入一次性的完整服务端副本，安装上述原版 CustomNPCs，在已同意 EULA 的独立新世界启动 NeoForge。测试器自动造跑道、生成实体、测量并请求停止服务器；**不要安装到正式服或包含有用世界的实例**。

测试源码：`tools/npc-rebuild/FollowerAudit.java`。结构化结果：`customnpcs-follower-results.json`。逐 tick 测量每 10 tick 落盘的轨迹在本地测试目录 `follower-trajectory.csv`。本次仅验证服务端运动和配置，不包含客户端动画、网络插值、复杂地形或多人压力测试。
