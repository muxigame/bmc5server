# 建筑档案 0.6.3

## 0.6.3 地基空气保护

载入建筑后，投影侧栏新增「地基：关 / 开」。默认关闭，保持原来的完整空气覆盖行为；开启后，底部指定层中的空气不参与本次放置，原地形及这些位置的容器内容保留。地基实块仍会替换原方块，地基以上空气仍会清空目标。该选项不改写建筑NBT或统计JSON，旧建筑无需重新导出。

「地基设置」显示地基层数和投影处的地基顶层世界Y。自动识别从最低处连续向上检查：同层实块须连通、均为无流体的完整碰撞方块，且没有被水平包围的空气；遇到不符合的层立即停止，不会跳到更高处的屋顶。底部全空气留白仅在其后确实识别到地基时一并计入。开放门洞、柱式地基、半砖及异形模组方块可能需要人工判断，可填层数并点「应用层数」，或点「自动识别」重算。0表示不保护。

开关在本次玩家登录期间保留；每次载入新建筑都会重新识别层数。旋转、镜像不改变层数。碰撞数量、确认提示和实际放置使用相同过滤数据；切换开关或层数会取消旧覆盖确认。放置前仍完整备份目标区域，撤销仍完整恢复备份区域。

客户端与服务器需同时使用0.6.3（网络协议5），不能只更新一端。当前运行中的游戏不会热更新；本轮仅交付候选，不替换运行整合包或远程服务器。

独立的 Minecraft 1.21.1 / NeoForge 21.1.250 模组，用于在游戏中保存建筑、还原建筑，并为建筑风格整理提供可读的数据。Java 21；客户端、服务端都安装同一 JAR。单人游戏也可用。

## 使用（0.3.0 远程投影）

1. 创造物品栏「建筑档案」取出「建筑档案仪」，或 `/ba give`。
2. 手持工具，**连续右键建筑的两个对角**。不必潜行，第二次点击后自动打开面板。箱子也可以选取而不会打开。选区包含角点所在方块。
3. 两个角应包含屋顶；也可先在地面选范围，在面板输入最低 / 最高 Y 并点击「应用上下高度」，再回现场核对边框。每边上限128格，总体积32768格。
4. 输入中文建筑名，点击「保存选区」。留空自动命名；同名不覆盖。保存后自动载入该建筑。
5. 旧建筑可从右侧档案列表点击载入，支持翻页。回现场瞄准64格内的目标表面右键，显示固定轮廓并打开调整面板。可按1格或5格向东西南北、上下移动，读出底部和顶部Y。点击「返回现场绕着看」可继续观察；右键空气重新打开调整面板。建筑从原点朝世界 +X / +Y / +Z 延伸。
6. 点击「确认放置」。目标有方块时需要两次点击覆盖按钮；提示会明确保存的空气也会清空目标方块。放置前自动保存原区域备份。
7. 「撤销上次操作」也需再次确认，会覆盖该区域之后的编辑。仅保存本次登录最后一次撤销；必须在原维度操作。
8. 「重新选区」清空旧角点和已载入建筑，然后返回现场选新建筑。

**右键空气或 `/ba` 随时打开面板**。潜行右键选第二角的旧操作仍兼容；潜行右键空气现在打开面板，不再立即导出。旧命令 export/load/list/preview/paste/undo/select/pos1/pos2 均保留。当前仍限创造或二级管理员，无合成配方。

面板显示当前步骤、角点、尺寸；载入后显示方块总数与种类，鼠标停在统计文字上可看前五种主要方块。手持工具时，选区和放置边框持续周期显示，并显示下一步操作提示。放置预览包含蓝色简化外形、黄色整体范围、绿色底面和红色原点。外形按方块格简化，暂不绘制真实材质或楼梯等细节；超过2048段时仅显示整体范围。微调后的原点不得离玩家超过96格，未加载区域不允许放置。

## 导出文件与建筑风格档案

文件实际位于 **世界存档目录/building_archive/**。单人游戏为 `saves/世界名/building_archive/`；专用服务器为其世界目录中的同名文件夹，可用「建筑导入导出器」下载到客户端。

- `house_01.nbt`：压缩的原版结构 NBT，保存每个方块的位置、ID、状态和方块实体数据（例如箱子内容）。这是重新导入的权威数据。
- `house_01.analysis.json`：可直接阅读、提供给其他开发对话或脚本处理的分析报告。
- `backups/undo_玩家UUID_时间.nbt`：每次放置前自动保存的原区域，重启后仍在磁盘。恢复旧备份时先把对应文件复制到 `building_archive/` 顶层，使用 `/ba load 文件名` 载入，在正确原点放置。

分析报告包含：尺寸、原坐标、维度、非空气数量、空气数量、方块实体数量、按注册 ID 汇总的数量、按模组命名空间汇总的数量、每个高度层的方块分布、完整状态调色板（包括朝向/半砖/含水状态等）。这些是**实际方块格数**，并非合成所需材料数量。

`styleTags` 与 `styleNotes` 留给人工记录建筑风格，例如中世纪石木、屋顶配色和墙面比例。模组只报告可测量的事实，不根据几个方块名称臆测建筑风格。分析文件不参与放置，编辑其中的风格记录不会改变建筑。后续规划可以同时提供 NBT、JSON 与建筑截图。

把 NBT 复制到另一个世界的同名目录，安装其使用的方块所属模组后即可 `/ba load`。可以载入同一 Minecraft 数据版本、单调色板、不含实体的原版结构 NBT。暂不直接支持 `.schem`、`.schematic`、`.litematic`，支持水平90°旋转和东西方向镜像。

## 范围与限制

- 每边最多128格，总选区体积32768格（含空气）。区域必须已加载，且在世界边界和建筑高度以内。
- 保存方块及其方块实体 NBT；不包含 NPC、生物、玩家、掉落物、画、盔甲架等实体，也不保存计划刻或外部模组数据库。模组机器引用外部网络的行为需要其自身支持。
- 严格检查缺失方块、无效属性、数据版本、坐标和调色板索引。不会把缺失模组方块静默换成空气。
- 使用原版结构放置，保持记录的形状和状态；建筑恢复后仍遵循游戏运行时的物理、流体与红石规则，不承诺复杂机器运行状态的完整快照。
- 选区、载入和单次撤销属于当前玩家会话；退出后清除。导出文件及磁盘备份不会清除。

## 0.4.0 旋转与删除

投影面板的左转/右转按钮每次旋转90°，标题显示当前角度。原点固定，长宽互换，预览和实际放置使用同一份旋转数据；不会修改磁盘原档案。原版方块状态朝向随之旋转，容器内容保留；不承诺第三方方块实体的私有朝向字段能自动转换。

删除记录：在档案列表中点击建筑名称旁的「删除」，核对完整名称后确认。只移除记录，不改动世界建筑。NBT及analysis.json移入世界存档/building_archive/deleted/独立备份目录，需要恢复时放回顶层并刷新。删除后清除所有玩家载入的同名记录和投影。


0.4.1 按用户澄清修正：删除的是已记录建筑的档案。移除主面板的世界选区删除入口，新增每条档案旁的具名删除确认。旋转继续保留。


## 0.4.2 列表内改名

点击记录旁的改名，在当前行输入名称，点保存或取消。支持中文、字母、数字、下划线及短横线，最多64字；同名档案或统计文件存在时拒绝覆盖。NBT和analysis.json一起改名，字节内容保持不变，包含用户填写的风格备注；已载入的同名会话同步更新名称并保留旋转/投影。网络协议2要求双端更新。


## 0.5.0 地形改造工具

创造分类「建筑档案」新增地形改造工具（钻石铲图标）。右键两个对角选长方体，右键空气打开面板，可补填最低/最高Y。每边最多128格，总体积32768格，区块必须已加载；创造或二级管理员可用。

- 替换指定方块：选择原方块和目标，仅匹配原方块ID的位置改变。
- 清理植物/薄雪：草、花、作物、藤蔓、地衣、悬根与薄雪；不砍树，不清实体、掉落物和液体。
- 填补空气：只填空气，不填水或岩浆。

方块选择器读取zh_cn中文翻译，显示图标，支持中文/ID搜索和翻页；未提供中文的模组方块明确标注。目标不可为容器、流体、门或两格高植物，新放方块使用默认状态并遵循后续物理。

先预览数量，核对边框，30秒内确认；方块变化则拒绝执行。容器/机器自动跳过，不产生掉落物。执行前完整区域备份到world/building_archive/backups/terrain_*.nbt。独立的地形撤销只恢复仍符合本次输出的位置，跳过后续改动，退出或换维度清除会话撤销。保存的建筑记录和档案仪选区不受影响。

## 0.6.0 游戏内导入导出（2026-10-27）
- 创造分类「建筑档案」新增「建筑导入导出器」（原版收纳袋图标）；`/ba give` 同时给档案仪与导入导出器，`/ba files` 可直接打开。
- 上传：右键新工具，浏览下载目录/桌面/其他文件夹，或在路径栏粘贴本地完整文件路径，选择 `.nbt` 或旧版收集脚本生成的作品 ZIP，然后上传。文件写入**当前服务器当前世界**的 `building_archive/`，无需服务器文件系统访问权。上传只登记档案，不直接放置方块。
- 下载：先用建筑档案仪保存选区，再在新工具的「下载已记录建筑」中点击建筑名。NBT和重新计算的方块统计JSON保存到**客户端游戏目录/建筑导出/**；可复制该目录路径定位文件。无需运行PowerShell或收集脚本。直接发送NBT即可，JSON便于建筑风格分析。
- 专用服务器：只有权限等级2及以上管理员可上传/下载；创造模式本身不授权传输。单人世界主人在创造模式下可用。服务端每个请求都会重新验证权限。
- 服务器同名文件不覆盖；可修改导入名称。ZIP多份建筑按原名逐个处理，遇到错误停止，已经成功的建筑保留。单份ZIP默认保留里面的建筑名，可手动改名。本地下载重名自动添加后缀。
- 每个压缩NBT最多8 MiB，解压NBT受32 MiB计数上限约束；每次ZIP最多64份、总量32 MiB。沿用128边长/32768体积、数据版本、缺失方块及属性检查。ZIP只读顶层NBT，不解压其他文件。JSON自动重建，手写风格标签需另存，不随传输保留。
- 网络协议升级至4，客户端、服务端都需更新到0.6.0。关闭窗口会取消当前传输；未完整接收/验证的文件不落入档案目录。
- 验证：41项后台GameTests通过；新界面编译通过，未启动可见游戏窗口进行人工界面验收。
