# 真实需求 0.5.2

Minecraft 1.21.1 / NeoForge 21.1.250，独立模组 `real_needs`。与工作区 CustomNPCs 联动，不替换其 JAR。客户端和服务器均安装；未安装 CustomNPCs 时仍可用 `/needs`。

0.5.2 将伤病持续扣血的受击反馈独立处理：不设置受击动作/行走冲击、不广播受击事件、不播放受伤音效，并在原版生命值同步之前同步静默生命值，避免客户端按生命下降再次制造受击动作和镜头晃动。已有真实攻击反馈不被清零，同一tick真实攻击正常反馈。生命、吸收/免伤、死亡和理智结算保留。网络协议4，须双端升级。

0.5.1 修复伤病周期扣血引发的原版随机击退：仅为 `real_needs:ailment` 添加 `no_knockback`、`no_impact` 标签。持续扣血保留生命伤害、受伤保护、理智损耗与死亡处理，不改变站立/行走/跳跃速度；正常攻击击退保留，已有伤病与参数不重置。

## 伤病与护理（0.5.0）

新增细菌感染、寄生虫感染、病毒感染、中暑、失温症、烧伤、骨折、刮伤、裂伤、淤伤、残废。轻/中/重三级，伤势按六部位独立记录，有不同资源损耗、出血或功能影响，以及护理、恢复与持续恶化。背包/Esc左上角 **伤病与护理**，也可右键护理用品打开。管理员可在此直接调试本人病情，不用指令；现有参数调试也增加了全部伤病规则。

新增10种可合成护理用品和专属创造分类。旧档不会凭空患病，旧健康值不自动转为残废；离线暂停，病情随重生/维度保留。详细规则、各病情效果、配方与配置见 [伤病说明](docs/illness.md)。客户端/服务端须共同升级至当前版本，协议4。

## 图形化参数调试（0.4.0）

不需要输入指令：打开背包或按 Esc，点击左上角 **真实需求 · 参数调试**。CustomNPCs 的 **真实需求** 页下方也有 **参数调试** 入口。

左侧按初始值、营养与睡眠、身材与肌肉、理智与免疫、疾病判定、体温、娱乐与气质、部位健康、食物厌倦与呕吐、威慑计算、显示阈值分类。可搜索中文名称或参数 ID，翻页编辑后点击 **保存修改**，一次保存全部分类中的修改。每行显示单位、范围，悬停显示默认值。周期同步、翻页、切换分类和窗口缩放均保留草稿。小窗口支持分类翻页。

支持20项初始值，以及全部已实现机制的增减量、时间间隔、倍率、环境修正、触发阈值和检测半径；威慑的初始值即基础值，实际显示继续叠加身体和装备。伤病规则见0.5.0说明，感染事件仍可供其它联动扩展。

设置共用于当前服务器存档，需要权限等级2才能修改；普通玩家可只读查看。保存后规则立即生效，初始值仅用于新玩家或旧角色缺失的字段，**不会重置现有角色进度**。恢复默认和撤销上次保存也在界面完成，上一版可跨重启恢复。恢复默认需要再次点击确认；放弃未保存修改有提示。多人同时修改时旧界面不能覆盖新配置，点击重读设置后再编辑。

客户端与服务端都升级到0.4.0（设置网络协议2）。设置持久化在 `world/data/real_needs_rules.dat`，旧存档自动为新参数补默认值。

## 角色系统与背包调试栏（0.3.0）

背包左侧显示20项：原五项需求，以及身材、肌肉、食物厌倦、理智、免疫、娱乐、体温、威慑、六部位健康、气质。勇气移除；旧体重迁移为身材。全部为0–100游戏值：身材/肌肉/体温/气质初始50，威慑20，厌倦0，其他新项100。生存和创造背包均可显示；服务器同步，旧档、重生和换维度保留。

已接入训练/每日消耗、独立扣血/死亡理智、免疫恢复与疾病判定接口、环境体温和近火取暖、逐食物厌倦与短暂呕吐、装备派生威慑、部位受伤和恢复、娱乐与气质变化。0.5.0起内置感染和伤病效果，同时保留扩展事件。完整规则、游戏日口径、默认分类与扩展方式见 [角色规则](docs/physiology.md)。

```text
/needs stat set TwoModTester physique 65
/needs stat set TwoModTester muscle 70
/needs stat set TwoModTester left_arm 80
/needs stat clear TwoModTester left_arm
/needs checks
/needs rules set immunity_seconds 420
/needs rules set boredom_limit 80
/needs rules undo
```

`stat set`和`clear`需要权限等级2，后者恢复该项初始值。字段：`physique muscle food_boredom sanity immunity entertainment temperature intimidation left_arm right_arm left_leg right_leg head torso temperament`。兼容旧`weight`命令别名；威慑会按装备和身体值自动刷新。全部生理参数用`/needs rules set`的Tab补全查看，保存和上一版回退持久化。合成书展开时侧栏紧凑显示；极窄窗口左侧空间不足时收起合成书查看。

## 使用

在 CustomNPCs 的任务日志、阵营页面或 NPC 主菜单右下角点击 **真实需求**，进入独立分页。也可输入 `/needs`。页面显示本人的蛋白质、能量、维生素、水分和睡眠储备、进度条与状态；返回按钮回到原页面。每秒由服务端同步，鼠标停在条目上查看补充方式与基础消耗。

五项均为 0–100，越高越充足，新玩家初始 100。20 以下标记不足，50 以下偏低。原五项营养实现记录、消耗与恢复，不因其不足附加伤害、药水惩罚或 NPC 自身需求（新增食物厌倦的反胃效果见角色规则），不替换原版饥饿值。创造、旁观及死亡时暂停消耗；离线不消耗。以游戏刻计时，20 tick 为一秒。

| 需求 | 每在线分钟基础消耗 | 恢复方式 |
|---|---:|---|
| 蛋白质 | 0.4 | 肉类、鱼类、兔肉煲每份 +18 |
| 能量 | 1.5 | 食物原版 nutrition × 3 |
| 维生素 | 0.5 | 水果、蔬菜等每份 +15 |
| 水分 | 2 | 喝完水瓶 +35；牛奶、汤 +20 |
| 睡眠 | 1 | 躺在床上每秒 +1；完整过夜恢复到 100 |

冲刺时能量和水分消耗乘 1.5。只有真正完成食用/饮用才补充，取消使用无收益；非水药水不补水。补充不突破 100。吃饭仍遵守原版饥饿值限制，满饥饿时通常不能吃普通食物；水瓶和牛奶仍可饮用。睡眠跳时不额外扣整夜的其他储备；未参与睡眠的玩家不会恢复睡眠值。

## 管理员配置

`/needs help` 显示命令说明。以下修改需要权限等级 2：

```text
/needs set <玩家> protein|energy|vitamins|water|sleep <0–100>
/needs rules
/needs rules set water 2
/needs rules set enabled 0
/needs rules set sprint 1.5
/needs rules set rest 1
/needs rules set food 1
/needs rules reset
/needs rules undo
```

五项同名规则是每分钟基础消耗（0–100）；`enabled` 为 0/1，停用冻结消耗和恢复；`sprint` 为 1–10；`rest` 为睡眠每秒恢复（0–100）；`food` 为所有食物/饮料补充的统一倍率（0–100）。修改后立即保存服务器世界的 `data/real_needs_rules.dat` 并回报成功。每次设置修改和恢复默认之前会保存上一版，`undo` 可切回，包括重启后。更早的版本可从联合实例完整世界备份恢复。

玩家数值存于各玩家持久 NBT 的 `RealNeeds`；随原版玩家存档保存。死亡、重生和换维度保留，避免以死亡刷新营养。服务器计算数值；客户端只可读取本人状态；参数编辑请求由服务端校验管理员权限、版本号、允许字段、有限数值和范围，整批通过后保存；不接受普通玩家修改角色值。

## 添加食物

通过数据包扩充 `data/real_needs/tags/item/protein.json`、`vitamins.json`、`hydrating.json`。已提供原版食物分类，并引用可选的 `c:foods/meat`、`c:foods/fish`、`c:foods/fruit`、`c:foods/vegetable`。未知模组食物如果有 FoodProperties 仍补能量，其他营养需正确标签。用数据包和 `/reload` 调整分类，不改 JAR。不依据物品名字猜测营养。

## 构建与验证

PowerShell：`./dev.ps1 build`，`./dev.ps1 runGameTestServer`。JDK 使用工作区 `dependencies/jdk-21.0.12.1+1`。发行包在 `dist/real_needs-0.3.0.jar`；GameTest 类及空白测试结构不进入发行包。`reports/` 保存验证记录。

联合测试实例固定为 `../npc-forging-test`。更新需先读取最新 `manifest.json`，正常停服并备份世界，然后使用 `Update-Mod.ps1 -ModId real_needs -JarPath <JAR>`，保留其他全部模组。UI 入口通过 NeoForge ScreenEvent 按工作区 CustomNPCs 页面类名添加；其他分支如改过类名可能只保留 `/needs` 入口。
